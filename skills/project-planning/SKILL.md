# Project Planning

1. Define the user problem, target users, desired outcome, and evidence that the problem exists.
2. Separate MVP, later enhancements, non-goals, and explicitly excluded work.
3. Map actors, permissions, data lifecycle, integrations, operating environment, and failure cases.
4. Identify legal, privacy, safety, security, accessibility, cost, and operational constraints early.
5. Verify compatibility before selecting platforms, APIs, frameworks, libraries, or hosting services.
6. Break work into phases with dependencies, owners, deliverables, and measurable acceptance criteria.
7. Identify reversible decisions and delay expensive lock-in until evidence supports a commitment.
8. Define test strategy, data migration, backup, rollback, monitoring, maintenance, and support responsibilities.
9. Estimate effort and cost as ranges with assumptions; do not fabricate certainty.
10. Track decisions, risks, open questions, and changes to scope.

## Output
Provide problem statement, scope, non-goals, architecture options, phases, dependencies, risks, acceptance tests, operating costs, and the next concrete action.
